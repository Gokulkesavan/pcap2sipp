    What gets templated vs. kept literal
    
      
      
    • Call-ID → [call_id]; UAC Contact host:port → [local_ip]:[local_port]. Compact header names (i:, v:, f:, t:, m:, …) are recognized and rewritten to long form.
      • 
      
    • UAC From tag → original tag text + -[call_number] (unique per run, keeps the original tag recognizable).
      • 
      
    • UAC Via → transport (UDP/TCP) preserved from the capture, extra Via params (e.g. rport, alias) kept; branch → literal token reused identically across every UAC message that shared the same branch (required for CANCEL and ACK-to-non-2xx).
      • 
      
    • To-tag on CANCEL → omitted. To-tag on ACK → [peer_tag_param], which SIPp expands to ;tag=<value> or empty string as appropriate.
      • 
      
    • ACK-to-2xx vs ACK-to-non-2xx is decided per transaction, matched by CSeq.
      • 
      
    • Re-INVITE (any UAC INVITE after the first, matched by incremented CSeq in the same Call-ID) is emitted as an in-dialog <send> with the SIPp [routes] pseudo-header, its own branch, and an annotation in the XML.
      • 
      
    • RFC 3312 precondition flows are detected when a 183 carries Require: 100rel, an RSeq header, and SDP with a=curr:qos/a=des:qos/a=conf:qos. A missing PRACK is a warning by default. Tick Synthesize PRACK to opt in to generating one (and its 200 OK) from the 183's RSeq and the INVITE's CSeq; every synthesized message is annotated in the XML.
      • 
      
    • Retransmitted messages are suppressed (duplicate method+CSeq+branch for requests; status+CSeq+RSeq+To-tag for responses).
      • 
      
    • All 1xx responses are emitted with optional="true", except the last non-100 provisional before a subsequent <send>, which is auto-promoted to mandatory (falling back to the last provisional if only 100 Trying is available).
      • 
      
    • Once Record-Route is seen on a ≥180 response, subsequent in-dialog UAC sends include the SIPp [routes] pseudo-header (except CANCEL and ACK-to-non-2xx).
      • 
      
    • SDP o=/c= IP → [media_ip]; m= ports → [media_port] / [media_port_N]; a=rtcp: templated to match.
      • 
      
    • If the capture is truncated at an INVITE final response, an ACK is synthesized.
      • 
      
    • IPv4 and IPv6 fragments are reassembled before SIP parsing; truncated messages (Content-Length > captured body) are flagged in Generation notes.
      • 
      
    • Timing preservation (optional, off by default) prepends a <pause milliseconds="N"/> before each message whose delta to its predecessor was ≥ 5 ms. Capped at 5000 ms per pause.
      • 
    
    
  
    

  
    
    Plain-text input & INVITE-only mode
    
      
      
    • Plain text. Any .txt / .log / .sip file (or pasted text) containing SIP messages is accepted. A message starts at a request line (INVITE sip:… SIP/2.0) or status line (SIP/2.0 183 …) and ends at the next one, at the end of its SDP, or when its Content-Length is satisfied. Text between messages is ignored. From there on it goes through exactly the same conversion as a pcap.
      • 
      
    • No network layer. UAC = topmost Via sent-by; UAS = first Route, else the Request-URI host (default port 5060). Direction comes from the From tag: the sender of the first request is the UAC; a request with a different From tag is UAS-originated; a response travels the opposite way to the request it answers. Message order is file order.
      • 
      
    • INVITE only. If the text holds no responses at all, the responses are generated: pick Any response (a branching scenario: optional 100/18x, then 200 → ACK → BYE, or any 3xx–6xx → ACK) or a fixed outcome such as 180 → 200 or 100 → 486.
      • 
      
    • Generated ACK / BYE use the INVITE's Request-URI, no Record-Route is assumed, and 401 / 407 are not retried with credentials. Auto-generated messages are marked in the XML comments and dashed in the ladder.
