Generation notes

    
    
    
  
    

  
    
    What gets templated vs. kept literal
    
      
      
    • Call-ID → [call_id]; UAC Contact host:port → [local_ip]:[local_port]. Compact header names (i:, v:, f:, t:, m:, …) are recognized and rewritten to long form.
      • 
      
    • UAC From tag → original tag text + -[call_number] (unique per run, keeps the original tag recognizable).
      • 
      
    • UAC Via → transport (UDP/TCP) preserved from the capture, extra Via params (e.g. rport, alias) kept; branch → literal token reused identically across every UAC message that shared the same branch (required for CANCEL and ACK-to-non-2xx).
      • 
      
    • To-tag on CANCEL → omitted. To-tag on ACK → [peer_tag_param], which SIPp expands to ;tag=<value> or empty string as appropriate.
      • 
      
    • Retransmitted messages are suppressed (UDP retrans of the same method+CSeq+branch, or the same status+CSeq).
      • 
      
    • All 1xx responses are emitted with optional="true", except the last provisional in any run that ends directly before a subsequent <send> — that one is auto-promoted to mandatory, because SIPp's own scenario validator refuses to load a scenario where a <send> is only gated by optional <recv> blocks. The promotion is annotated in the generated XML.
      • 
      
    • Once the SBC's Record-Route is seen on a ≥180 response, subsequent in-dialog UAC sends include the SIPp [routes] pseudo-header (except CANCEL and ACK-to-non-2xx). The original captured Route: header is dropped in that case so you don't get a duplicate.
      • 
      
    • SDP o=/c= IP (v4 and v6) → [media_ip]; first m= port → [media_port], additional m= lines → [media_port_N]; a=rtcp: templated to match. Everything else is reproduced byte-for-byte.
      • 
      
    • If the capture is truncated at an INVITE final response, an ACK is synthesized so the scenario terminates cleanly against the SBC.
      • 
      
    • Known gaps: PRACK is only generated if the capture shows the UAC sending one; TCP reassembly handles sequence-ordered, deduped, non-overlapping segments but does not do a full stack (gaps are flagged).
